# Task 080 implementation audit

Audit baseline: `ec615a1825a6575d6a2f18083b2a443590c05c34` (2026-11-24).
This audit treats source and executable tests as evidence; earlier task text and
`STATUS.md` are not proof by themselves. No physical audio, MIDI, controller or
touchscreen hardware was used.

## Classification

- **Implemented and tested (IT):** a production path exists and deterministic
  tests assert a resulting state, timing or audio property.
- **Implemented, insufficiently tested (IU):** the path exists, but tests are
  shallow, simulated, or assert command acceptance rather than the result.
- **Partial (P):** only a useful subset of the operation is exposed.
- **Backend-only (B):** application/engine support exists but Slint cannot
  perform the workflow.
- **UI-only/placeholder (U):** a visible control or label has no complete
  semantic operation behind it.
- **Missing (M):** no suitable production path was found.
- **Hardware validation required (H):** software evidence cannot establish the
  claim.

## Executive result

NEUROGENIC has a broad, coherent engine and application layer. Deterministic
tests exercise sample/synth playback, sequencing, mixer/group routing, native
FX, modulation, presets, recording, audio clips, live looping, performance
launching, project round trips and controller simulation. The production
executable can select headless, SDL3 or Slint while sharing one
`ApplicationService` (`apps/neurogenic.cpp`, `run_slint_frontend()`).

The initial Slint rollout is not yet a standalone-instrument workflow surface.
Its strongest pages are Sample, Mixer and basic FX-chain editing. Essential
operations still require semantic calls, CLI configuration, or pre-existing
project content: recording has no Slint action chooser; step pages beyond the
first 16 are not navigable from the touchscreen; modulation sources and macro
assignments cannot be created; preset save/mutation is absent; MIDI routing and
controller-map editing are absent; and no touchscreen keyboard is implemented.
The renderer is compiled in the opt-in Slint preset but not in the Nix/CI
package (`flake.nix` sets `NEUROGENIC_ENABLE_SLINT=OFF`).

No confirmed P0 data-loss, crash, or audio-callback defect was found in this
documentation audit. Several P1 workflow blockers and concurrency/performance
risks require focused follow-up; see `PRIORITIZED_BACKLOG.md`.

## Eight-page audit

### Performance — P

IT: play/stop, track selection, stable-ID slot launching, scene launch,
quantization cycling, session ownership display and return-to-arrangement are
wired in `performance_page.slint`, `slint_frontend.cpp` and
`SlintFrontendAdapter`. `tests/slint_adapter_tests.cpp` covers dispatch and
state; `tests/performance_launching_tests.cpp` covers backend timing.

B/P: performance capture, arrangement recording, ordinary audio recording and
live-loop recording all have backend actions in `ActionRegistry`, but the page
has one Record button and `transport_record()` deliberately returns “no single
semantic action.” Macro values are only exposed on FX, not Performance. Slot
state shows playing/queued/stopped, but recording state is only global shell
text. Gate releases are not generated by the touch slot component (it invokes
press only).

### Sequencer — P

IT: select/toggle step, select pattern, create/duplicate pattern, edit velocity
and duration, cycle resolution, inspect arrangement clips and show playhead.
Backend tests cover probability, conditions, ratchets, locks and automation
(`tests/tests.cpp`).

B: `step.page-next.v1`, `step.page-previous.v1`, probability, condition,
ratchet, timing-offset and lock actions exist but have no page controls.
Pattern rename/delete/length editing and arrangement clip move/resize/create are
not exposed. Arrangement selection is local UI state only. Thus a touchscreen
user cannot edit beyond the displayed 16 steps even though the model carries
`step_page`.

### Sample — P

IT: slot selection, WAV path load/replace, callback-acknowledged metadata,
bounded waveform overview, slice insertion/deletion/selection/pad assignment,
region bounds/fades/loop, preview, transient start/apply/discard, and starting
normalize/reverse/trim jobs. Backend analysis/processing tests use numerical
assertions.

P/B: waveform click inserts a fixed quarter-second slice; existing markers
cannot be dragged, horizontal navigation is not exposed, and renderer data
collapses min/max peaks into magnitudes (`publish()` in
`src/ui/slint_frontend.cpp`). Candidate editing, quiet/equal/grid analysis,
region create/delete, processing cancel/progress/result save/publication, and
record/resample controls are backend-only. “Normalize/Reverse/Trim” start jobs
but do not publish their result into a slot, so the visible workflow is
incomplete. Preview position is not observable.

### Sound — P

IT: switch the selected track between sampler and subtractive synth, edit
discovered synth parameters, and adjust a small sampler subset (mode, pitch,
attack, release). Existing local modulation routes can be selected, enabled,
depth-adjusted and removed. Transactional preset validate/prepare/apply is
available by typed path and ID.

B: full sampler settings, synth voice/polyphony controls, voice-local
modulation definitions, modulator creation and route creation are not exposed.
Preset enumeration is on Browser; save current instrument, rename and delete
have no semantic adapter. The visible “Save Current” intentionally fails.

### Mixer — P/IT

IT: stable track/group/aux/master presentation, selection, banking, track and
group gain, pan where supported, mute/solo, two aux sends through contextual
operations, track-group assignment, output routing, meters, and external-loop
wet/bypass controls. Adapter tests verify acknowledged state and invalid route
rejection.

P: only Aux 1 is directly visible in the page body; group creation/deletion and
renaming are backend-only. The presentation model contains a fixed three-pair
label array even though routing validation uses actual available channels.
Meter tests copy simulated snapshots; refresh cadence, decay and physical I/O
accuracy are unvalidated.

### FX — P

IT: owner selection, native gain/delay/filter/saturation insertion, removal,
reorder, bypass, descriptor-driven parameter adjustment, existing source/route
selection, route create/depth/enable/remove, macro value adjustment, and
external-loop controls.

B: the backend registry supports more descriptor-driven discovery than the
four hard-coded add buttons. Modulator creation/configuration/deletion, macro
creation/assignment/scenes/morphing, effect preset save/apply, and parameter
reset are not exposed. Route creation chooses the selected source and parameter
but offers no output/depth/range workflow before creation.

### Browser — P

IT/IU: bounded (512-entry) non-recursive navigation, parent, category filter,
name/type/date sort, project open/save/save-as/new with dirty confirmation,
sample load, and preset enumeration/validate/apply. Tests use temporary files.

P: directory scanning and preset enumeration are synchronous on the Slint
event loop. There is no pagination after truncation, persisted recent-location
UI, sample metadata/preview, preset save/rename/delete, missing-asset relinking,
removable-media event handling, or native picker. “Other” has no content-specific
operation.

### Setup — P

IT/IU: copied active audio status, requested device/channel/buffer preferences,
fixed 48 kHz display, restart-required state, MIDI device enumeration,
internal/external clock toggle, controller list, MIDI learn start/cancel,
profile save, preference save/revert, diagnostics and guarded exit.

P/B: selecting MIDI devices only stages preference strings; the page cannot
edit MIDI routes, channels, clock output/forwarding, external instruments,
controller semantic targets, pickup or mapping removal. Learn requires manual
logical-control ID and mode text. Profiles can be saved but not selected/loaded
from the page. External-FX configuration remains on Mixer/FX. No touchscreen
keyboard exists, making path, ID and mode fields impractical on an appliance.

## Highest-impact blockers

1. Recording, resampling and live-loop modes cannot be initiated coherently
   from Slint (`AUD-001`).
2. Touch-only sequence editing stops at 16 steps and omits core step properties
   (`AUD-002`).
3. Preset creation/mutation and processing-result publication are incomplete
   from Slint (`AUD-003`, `AUD-004`).
4. MIDI routing/controller mapping configuration requires textual IDs, CLI or
   prebuilt profiles (`AUD-005`).
5. No touchscreen keyboard/path chooser makes the Browser, Sound preset and
   Setup workflows terminal-dependent (`AUD-006`).
6. The production Nix/CI path does not build Slint, and rendered/touch behavior
   has no automated coverage (`AUD-007`).

The deferred shared granular DSP investigation remains on the roadmap; no
granular design or implementation is part of this audit.
