# Task 097B validation

Task 097B closes the production graphical entry points that can be backed by
the existing Performance-bank and active controller-profile services. It does
not invent a frontend-owned controller profile library. All physical hardware
results remain **NOT RUN**.

## Ownership and implementation

`AssignmentTargetPicker` is the shared copied metadata source. Performance
confirmation dispatches project semantic actions and enters unified musical
history. Setup confirmation calls the appliance `ControllerCoordinator`
services and never enters project history. Pending forms retain stable bank,
position/layer or endpoint/source identity. Conflict replacement retains the
candidate and the active mapping until explicit confirmation.

## Generated and rendering evidence

The production generated component test iterates all 48 chooser rows, checks
stable row ownership, and cancels without mutation. It authors P1/P8 primary and
secondary parameters, F1/F8 primary and secondary safe typed actions, and
PAD1/PAD16 launch targets. The Setup fixture selects a mapping, applies a shared
target, opens a structured conflict, cancels it, reopens and confirms it, and
exercises MIDI-learn start/cancel. Both 1920x1200 and 1024x600 software-rendered
tests pass. These are generated callback and structured software rendering
results, not coordinate-driven touch or physical-controller validation.

## Remaining gaps and Task 097C

RC2-005 graphical position selection and supported assignment forms are closed
in software. RC2-006/AUD2-006 remain **Partial** only for the missing
coordinator-owned profile library/recovery authority, richer learned-source
preview, dedicated context/modifier scope fields not represented by the current
profile schema, and feedback modes beyond the supported boolean destination.

pad modes for all sixteen destinations. It must keep separate rows for existing
bindings, missing stable metadata, missing presentation, missing musical
